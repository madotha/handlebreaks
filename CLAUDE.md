## Keep the repo generic

The repo is published on GitHub (`git@github.com:madotha/handlebreaks.git`, MIT license) and meant to be installed on any machine. Commits use the pseudonym set in the repo's local git config; never commit real names, personal email addresses or other personal data. It must stay free of anything specific to one host or person.

- Don't commit host-specific facts, setup notes or TODOs about a particular machine. This covers usernames, home paths, mounted shares, installed versions and the state of a local install. Mention them in chat or put them in the local `TODO.md`.
- Secrets (tokens, passwords, keys, `.env`) and local config or overrides go in files that `.gitignore` covers. When adding a new file or directory of that kind, or one not needed to install the tool elsewhere (runtime output, caches, editor files), add it to `.gitignore` in the same change.
- When code needs a machine-specific value, prefer a gitignored local file plus a committed example over hard-coding it.

## Versioning and changelog

- Semantic Versioning `vX.Y.Z`. The single source of truth is `__version__` in `encoding.py`, shown by `python3 encoding.py version`. It covers the whole tool, including `encode.sh`, `status.sh`, the plist and `preset.json`.
  - MAJOR: incompatible changes, such as the `state.json` schema, the queue, results or `current.txt` file formats, renamed or removed subcommands, or anything that requires reinstalling the launchd agent.
  - MINOR: new backward-compatible features, subcommands or options.
  - PATCH: bug fixes and small adjustments, including changes to filters or presets that don't change the behaviour of the interface.
- Every user-visible change gets an entry under `## [Unreleased]` in `CHANGELOG.md` ([Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format: Added, Changed, Deprecated, Removed, Fixed, Security). Pure doc or repo housekeeping doesn't need one.
- To release:
  1. Bump `__version__`.
  2. Rename `[Unreleased]` to `[X.Y.Z] - YYYY-MM-DD` and add a fresh empty `[Unreleased]` section.
  3. Check the README against the release: setup steps, requirements and settings must work for the new version, and every release with manual steps (MAJOR releases, changed plists, `.env` keys or mounts) needs an `Updating from version X` section in the README describing them.
  4. Commit as `Release vX.Y.Z`.
  5. Tag that commit with an annotated tag `vX.Y.Z` (`git tag -a vX.Y.Z -m "vX.Y.Z"`).

  Every release commit must carry its tag. Never bump the version without tagging, and never tag a commit that isn't a release.

## HandBrake compatibility

The preset editor must cover every setting of the newest HandBrake. Whenever a new HandBrake release comes out (CLI, macOS or Windows app), and before each release of this tool:
1. Check the latest HandBrake version and its release notes (handbrake.fr/news.php, GitHub releases): new settings, encoders, filters, renamed or removed values, a new preset format (`VersionMajor`).
2. Run `python3 encoding.py preset-check` (and `--worker` with a published worker file) with the newest HandBrakeCLI. "Settings without an editor field" must be "none": add each new setting to `editor_schema()` or `audio_track_schema()` with a label, kind, choices and, if it only exists in newer versions, a hint saying so. Old settings HandBrake still exports go into `LEGACY`.
3. Encoders tied to a platform or hardware need an entry in `PLATFORM_NOTES` (e.g. new hardware encoder prefixes from the Windows or macOS app), and new Apple-only audio encoders an entry in `AUDIO_ALIASES` if HandBrakeCLI elsewhere falls back to another encoder.
4. Import a preset exported from the newest macOS and Windows apps, check that an unchanged save changes nothing and that `preset-check` reports it fully supported (or explains why not).
5. Note the result in the changelog; update the Docker image's HandBrakeCLI if a newer one is available for it.

## Overview

Semi-automatic H.264 → H.265 (x265) re-encoding of a Plex library with HandBrakeCLI. It runs natively on macOS (launchd) or in Docker. Python 3.9+ plus zsh scripts. `encoding.py` and `encode.sh` use only the standard library and system tools. Only the web UI needs packages (`requirements.txt`: Flask, waitress). ffprobe (ffmpeg) is optional but needed for codec data. There is no build system, linter or test suite; test changes manually in an isolated data folder (`ENCODING_DATA_DIR=<scratch dir>`), and for Docker, with a separate compose project (`docker compose -p <name>`).

**Everything is in English**: code, comments, CLI and log output, the web UI, the Obsidian notes, configs, README and other docs. Don't add German anywhere. The only exceptions are `LEGACY_PREFIXES` and `LEGACY_NOTE_HEADING` in `encoding.py`, which must match data written by version 1.x. The README is the full from-scratch setup guide for all three setups (native, Docker, Docker + native encoding); update it whenever setup steps, requirements, settings or commands change. New users and updaters rely on the README alone: whenever a change affects how the tool is set up, configured, updated or migrated (new requirements, settings, mounts, files to reinstall, data migrations), update the README in the same change, including its **Updating** section. The README starts with a screenshot of the Files page (`docs/screenshot-files.png`): whenever the Files page changes visually (layout, columns, colors, controls), retake it in the same change. Never use a real library for it: run a demo instance with the made-up data from `docs/demo_data.py` (instructions in its docstring) in an isolated data folder, open Shows → Northwind Station (2018) → Season 02, tick three offered files, and capture at 1280 px width, dark mode. Its **Quick start (Docker)** and the **AI coding agent prompt** are the entry points for new users: keep both in sync with any change to setup, requirements or settings.

## Commands

```bash
python3 encoding.py scan [--json] [--no-probe]   # scan NAS (+ ffprobe), refresh list, DB and Obsidian note
python3 encoding.py queue all -3 -7 --skip-rest  # queue by number from last scan (also: 1,2,5-8)
python3 encoding.py skip 4 | skipped | unskip 2
python3 encoding.py status
python3 encoding.py version                      # print __version__ (also --version, -V); works without config
python3 encoding.py import-legacy <cache.json> <note.md>   # one-time migration from old encoding_todo.py
zsh encode.sh                                    # run the worker manually (normally launchd or the Docker loop)
zsh status.sh                                    # live terminal progress view
python3 webui.py [--host H] [--port P]           # web UI, default 127.0.0.1:7979 (needs requirements.txt)
docker compose up -d --build                     # Docker: everything in one container
docker compose -f docker-compose.yml -f docker-compose.hybrid.yml up -d   # Docker UI/scan + native Mac encoding
```

Running `scan` or `queue` has real side effects (writes `encoding.db`, the Obsidian note, and `queue/` batches that a worker immediately picks up and starts encoding). Don't run them casually against a real install.

## Architecture

Processes coordinate only through files in the data folder (`DATA_DIR`: the program folder, or `$ENCODING_DATA_DIR`, `/data` in Docker):

- **`encoding.py`** (controller and core library): walks the shares (`shares()` from `SHARE_N` settings), gets size and mtime per file and probes new or changed files with ffprobe (`inventory()`, `FFPROBE_WORKERS` in parallel with the lighter `PROBE_ARGS`, cached by size and mtime in the DB). It classifies each video, stores everything in SQLite and writes `Encoding To-Do.md`. On `queue` it writes `queue/batch-<timestamp>.txt` via a temp file in `DATA_DIR` plus `os.replace`, so a worker never sees a partial file. `scan()` takes a `flock` on `.scan.lock`, so web and CLI scans can't overlap. Replacing originals is a job handoff because the web UI may not write to the library: `POST /replace` validates and calls `encoding.request_replace()` (writes `replace/<id>.json`); `encode.sh` runs `encoding.py replace-jobs` (`run_replace_jobs()`: file moves only, no database) at start and every minute while encoding, writes `replace/done/<id>.json`; the dialog (`_replace_dialog.html`) and its script (`static/replace.js`, `window.ReplaceDialog.attach(root, {say, done})`) are shared by the Files page (reloads the folder level when done) and the Status page (`replace_info()` marks finished rows with their encode or as replaced via `encoding.replaced_keys()`; reloads when done). The page polls `/replace/<id>` for the job's result. Bulk replace (`_bulk_replace_dialog.html`, `static/bulkreplace.js`, `window.BulkReplace.open(formData, {say, done})`): `POST /replace/preview` lists files with a finished encode (ticked `key`/`folder` values expanded with the filters, or `all=1` = every non-`h265` file whose stem has an encode; the `waiting` status is only set by scans, so files encoded since the last scan are still `queued`, and `level_context()` shows them as `waiting` too) with suggested names (codecs probed in parallel), `POST /replace/bulk` validates all rows (unknown, pending, missing encode, bad or duplicate name) before creating any job. `run_replace_jobs()` moves all jobs of a run first (writing each result at once), then calls `plex.notify_replaced_many()`, which analyzes same-name items and scans each folder once. Name fields are single-line textareas made by `window.nameField(field, onEnter)` (`replace.js`): they grow with the text, Enter submits, line breaks are stripped. The dialog pre-fills the encode's name, then asks `/replace/suggest?key=…` for `encoding.suggest_name()` (codec of the encode via ffprobe; keeps the field if it was edited meanwhile). Bringing the result into the DB is the web UI's job, not the page's: `sync_replaces()` (under `REPLACE_SYNC`) rescans the folder of every finished job without `synced` (`unsynced_replaces()`), then sets `synced` in its `replace/done/` file (`mark_replace_synced()`); it runs every 10 s in `replace_sync_loop()` and from `/replace/<id>`, and returns False (retry later) while another scan holds the scan lock. Pending jobs (`pending_replaces()`) show as "Replacing…" instead of the button; `clear_results()` keeps unsynced job results. `replace_one()` never overwrites another file, keeps or deletes the original, and rolls back on failure. Afterwards it calls `plex.notify_replaced()` (only with `PLEX_URL`/`PLEX_TOKEN`): `plex.Plex` maps the target path to a library by its folder paths, finds the item by walking `/library/sections/<id>/folder` (the folder view merges all folders of a library), and calls `PUT /library/metadata/<ratingKey>/analyze` for a same-name file, otherwise `/library/sections/<id>/refresh?path=<folder>`. The token goes only into the `X-Plex-Token` header; never print or log it. `PLEX_URL` may list several addresses, the first answering one is used. `scan(path=key)` checks one file or folder (the web UI's ↻ buttons, always with `force`): it walks only that path (guarded against leaving the share), replaces only its rows, and doesn't touch `last_scan` or the per-share scan times. `scan(only=[prefixes], force=…)` scans single shares: `save_files()` then replaces only those shares' rows, the offered list and summary are rebuilt from the whole `files` table, and `force` skips the ffprobe cache. The last scan time per share is stored in `meta` as `share_scan:<prefix>`. `load_config()` also migrates a version 2.x `config.env` (`migrate_v2()`, under `.migrate.lock`) and makes sure a preset and `DEFAULT_PRESET` exist. `write_config()` is the only writer of `config.env` (web UI and migration).
- **`presets.py`**: the preset store, `presets/<id>.json` in the data folder, each a HandBrake export file with one preset. The id is a slug fixed at creation; shares and batch lines refer to it, so renaming is safe. It also reads what the installed HandBrakeCLI supports (`capabilities()`: encoders, encoder speed presets, containers, mixdowns, preset format version; `builtin_presets()`; `from_builtin()` via `--preset-export`), cached on disk in `.handbrake-cache.json` (`_disk_cache()`, keyed by the HandBrakeCLI path, size and mtime), and `verify()` makes HandBrakeCLI load a preset before it's saved. Nothing about HandBrake's options is hard-coded except `FALLBACK` for machines without HandBrakeCLI. The editor is schema-driven: `editor_schema(caps)` lists every setting per tab (`F(key, label, kind, options, hint, show, **attrs)`; kinds text, int, float, bool, select, langs, multi, json; options may depend on another field, `show` hides a field unless another has given values, `!x` = not), `audio_track_schema()` the fields of one `AudioList` entry. `editor()` resolves values and choices for the template (`preset_edit.html`, `static/preset_edit.js`: tabs, dependent selects, show rules, tracks named `a<n>-<key>` with `a<n>-_orig`), and `apply_form()` parses the form back (`_store()` keeps unchanged values exactly and doesn't add unset defaults, so an unchanged save is a no-op; settings outside the schema except `INTERNAL` are edited generically under "More"). `capabilities()` also reads per-encoder tunes, profiles and levels, filter presets and tunes, sample rates, dither methods, the HandBrake version, the platform and every setting the CLI knows (`preset_keys`/`track_keys`, from its own preset export); `encode.sh` publishes the worker's capabilities to `handbrake-worker.json` (`encoding.py handbrake-caps`, in the background, only when HandBrakeCLI changed), and `webui.encodes_here()` decides whether the editor uses this machine's or the worker's (`presets.editor_capabilities()`: Docker with `WORKER_ENABLED=0` uses the worker file; then `verify()` only checks against its lists). `editor()` marks fields the encoding CLI doesn't know (`unsupported`), `compatibility()` describes the encoding CLI and notes for the preset (newer preset format, ignored settings, unavailable values, `PLATFORM_NOTES`), `audit()` backs `encoding.py preset-check`; bump `CAPS_VERSION` when it returns new keys (it's part of the disk cache key).
- **`encode.sh`** (worker): started by launchd (`local.plex-encoding.plist`, `QueueDirectories` on `queue/`) or by the loop in `docker-entrypoint.sh`. It moves batches `queue/ → processing/ → done/`, encodes into `<ENCODED>/.inprogress/` and moves the file to `<ENCODED>/` only on success. A `mkdir`-based `.lock` (stale-PID cleanup) keeps it single-instance. It uses `caffeinate` where available, and exits or sleeps if the NAS, HandBrakeCLI or `config.env` is missing, so it gets retried.
- **`webui.py`** (Flask, served by waitress): imports `encoding` as a module and reuses its functions (`load_files`, `current_progress`, `queued_keys`, `recent_results`, `scan`). It reloads `config.env` on every request. Scans run in a background thread (`start_background_scan()`); `auto_scan_loop()`, started in `main()`, checks once a minute whether `SCAN_INTERVAL` minutes have passed since `last_scan` and starts a scan of all shares. Stored times are naive server-local strings (`now_str()`, `encode.sh` `date`); the `localtime` filter renders them as `<time datetime=…>` with the server's UTC offset, and `static/time.js` shows them in the viewer's time zone. The Status page's queue comes from `all_queue_items()`: `awaiting_review()` (files with an encode in the output folder, from earlier runs too, as `OK` entries without a number; cached by DB and output folder mtime) plus `encoding.queue_items()` (entries before `current.txt`'s number are finished, using their result; `/status/live` is a small JSON snapshot polled by `static/status.js`; `/status/queue` returns pages of rows). The Files page never renders the whole library. `/files` renders the top level only, and `/files/folder?path=…` returns one folder level (`_level.html`: subfolders plus the first `PAGE_SIZE` files) (subfolders paged by `FOLDER_PAGE`; with `dirs=N` only the next folders plus a new "Show more folders" button, which `files.js` swaps in) or, with `rows=1`, the next page of file rows (`_file_rows.html`, next URL in the `X-Next` header). `static/files.js` fetches a folder when it's opened. `tree_level()` also counts per folder `optimized` (status `h265`), `unknown` (not probed) and `other`, which `_level.html` shows as the folder's status bar and badge. Sorting: column headers cycle ascending → descending → off via `next_sort()`; `sort_args()` reads `sort`/`dir` (`{}` = default order), `tree_level()` orders files with `SORT_FIELDS` (and folders with `FOLDER_SORT`) via `sort_rows()` (missing values last, name as tiebreak); folder URLs carry filters and sort (`link_args`). The Status queue sorts the same way on the server (`QUEUE_SORT`); small fully rendered tables use `<table data-sortable>` with `static/tablesort.js` (cells may carry a raw `data-sort` value). `files.js` never opens folders by itself (every page load starts collapsed; `openSet` lives only in the page and reopens folders when their level is reloaded after ↻ or Replace…); it also keeps each loaded folder's HTML there, tagged with the page's `data-version` (hash of the server's start time, `enc.db_version()` and the queue), so reopened folders need no request until the data changes (↻ reloads bypass it). Folder URLs are built in JS from `data-folder-url` + `data-folder-query` (kept out of every row to slim the markup). `sort_state()` remembers the Files and queue sort in the Flask session (`sort=none` = off); `tablesort.js` stores client sorts in `localStorage`. `cached(name, version, compute)` keeps `library_summary()` and the unfiltered top level until `enc.db_version()` changes; `tree_level()` and `/stats` aggregate in SQL. `compress()` gzips HTML/JSON responses over 2 KB; `squeeze()` collapses whitespace between tags in folder responses. Don't use `content-visibility` on folder rows: with `<details>` it left opened folders blank in some browsers (Safari); the paging keeps levels small enough without it. **Collapse all** (`data-collapse-all`) closes all folders, clears the remembered open set and empties top-level folder bodies unless they contain ticked inputs. Status housekeeping: `POST /queue/remove` (`key` values or `all=1`) and `POST /results/clear`. All filtering goes through `filter_sql()` (date added: `file_filters()` reads `added` = 24h/7d/30d/custom with `from`/`to` in dd.mm.yyyy, `added_bounds()` turns it into epoch bounds, `added_problem()` reports invalid input; the `added` template filter renders `<time data-format="dmy">` for `time.js`): text via a Unicode-aware `pylower()`, codec as a list of names, `unknown` or the `CODEC_GROUPS`, and status. A folder path is turned into a key range (`key >= 'p/' AND key < 'p0'`) that uses the primary-key index. `POST /queue` takes `key` values (validated against the `files` table, so no arbitrary paths reach `encode.sh`) and `folder` values, which are expanded on the server with the submitted filters. It then calls `encoding.write_batch()`, the same function the CLI `queue` uses. In the browser, a ticked folder disables the inputs below it, so they aren't submitted twice. Design system (`static/style.css`): color tokens on `:root`, dark values under `:root[data-theme="dark"]` and `@media (prefers-color-scheme: dark)` (guarded by `:not([data-theme="light"])`); the inline script in `base.html` applies the saved theme before paint, `static/theme.js` cycles system/light/dark. Amber (`--accent`) is only for actions; status and codec colors have their own tokens. `[hidden]` always wins (`display: none !important`), so elements with a flex class can be hidden by the attribute. Phones are `max-width: 720px`: `.tabbar` replaces the header tabs, file rows (`_file_rows.html` cells `c-codec`, `c-res`, `c-bitrate`, `c-dur`, `c-size`, `c-added`, `c-status`, details via `data-label`) become two-line flex rows that `files.js` expands on tapping the name, and `.queue-table`/`.preset-list` stack. Icons come from `templates/_icons.html`: `sprite()` is rendered once in `base.html`, `icon('name')` only references a symbol (`<use href="#i-name">`), so add new icons as symbols there and import `icon` in every template or partial that uses it. Icon-only buttons (`.icon-btn`, `.icon-lg` for bordered ones) need `aria-label` and `data-tip`; `static/tooltip.js` shows `data-tip` on hover and keyboard focus (hidden on phones). Primary and destructive actions keep text labels. the logo and favicon are `static/favicon.svg`. File names go through the `wbr` filter (break opportunities after `.`, `_`, `-`). After visual changes, check desktop and a 390 px phone width in both themes for horizontal overflow. `/stats` computes all chart data in Python (`chart()`), and the templates render it as plain HTML/CSS bars, without a chart library or CDN. The chart colors are validated for color-blind safety in light and dark mode (`--viz-*` tokens in `static/style.css`), so re-validate them if they change. Codec color coding everywhere follows `codec_class()`: `encoding.OPTIMIZED_CODECS` → green, other → orange, not probed → gray. Settings → Library lists shares from `share_list()` (raw config values, `path_checks()`, preset name, `share_info()`); each share is a `<details>` card whose form posts to `POST /settings/shares/<n>` (`n` = number or `new`, which gets `next_share_number()`), and `POST /settings/shares/<n>/delete` comments a share out (never the last one); scan and delete buttons in the card's summary use the hidden form `#share-action` via `form`/`formaction`. Settings are written back into `config.env` (`write_config`), keeping comments. `FORBIDDEN_RE` blocks anything zsh would execute when sourcing the file. All POSTs need a session CSRF token. The session key is in `DATA_DIR/.secret_key`. There's no login yet (TODO P3), so it binds to 127.0.0.1 by default.
- **Docker**: `docker-entrypoint.sh` creates `config.env` from the template, runs the worker loop (every 30 s, if jobs exist and `WORKER_ENABLED` is 1; the env var overrides `config.env`), and then `exec`s the web UI. The image is Debian 13 with HandBrakeCLI 1.9.x, which maps the preset's `ca_aac` to `av_aac` on its own. `docker-compose.hybrid.yml` bind-mounts the native install folder as `/data`, forces `WORKER_ENABLED=0` (the cross-VM `.lock` PID check would not prevent two workers), and moves the DB to its own volume (`ENCODING_DB_FILE`), because SQLite must not be shared across the Docker VM boundary.

**SQLite (`encoding.db`, WAL)**, schema in `SCHEMA`:
- Tables:
  - `meta`: `last_offer` JSON, `last_scan`
  - `baseline`, `skipped`, `known`
  - `results`: imported from `results.tsv` on every `load_results()`
  - `files`: inventory with ffprobe fields, `status` ∈ `STATUS_LABELS` and `added` (epoch, first seen: kept by `inventory()` across scans; the scan time for new files, the file's mtime on a share's first scan; `migrate_added()` adds the column to older databases and fills it from `mtime`; `sync_replaces()` copies it to a replaced file's new key)
- `load_state()`/`save_state()` keep the old `state` dict interface.
- A v1 `state.json` is imported once by `migrate_state_json()` and renamed to `state.json.migrated`.
- Changing the schema or these meanings is a MAJOR change.

macOS quirk: when launchd starts `encode.sh`, `/bin/mv` and `/bin/rm` get "Operation not permitted" on the NFS library/output share, while Python's `os`/`shutil` calls work (verified with `launchctl submit`). Every file operation on the share in `encode.sh` must use the `fs` helper (Python); plain `mv`/`rm` are only fine for local files (queue, logs, lock).

Shared file contracts (change both sides together):
- **Keys**: every file is identified as `share<N>/<rel path>`, where N is the share number from `SHARE_N`. Names (`SHARE_N_NAME`) are display-only. The numbers are part of stored keys, so they must never be renumbered or reused: the web UI comments out removed shares, and `next_share_number()` skips any number that appears in `config.env`, even commented out. Batch files contain one entry per line: `key` or `key<TAB>preset id` (an override chosen when queueing). `encode.sh` looks up the prefix in `ROOTS` and picks the preset as override, then `SHARE_N_PRESET`, then `DEFAULT_PRESET`; `status.sh` and `queued_entries()` read the same format. Keys from version 1.x (`Filme/`) and 2.x (`Movies 2/`) are translated by `legacy_key()` with the `v2_prefix_map` stored in the `meta` table, whenever old `state.json` or `results.tsv` lines are imported.
- **`logs/results.tsv`**: `date \t STATUS \t key`, status ∈ OK/FAIL/MISSING/EXISTS/STOPPED. Written by `encode.sh`, imported into the DB incrementally (byte offset in `meta` `results_offset`, reset when the file shrinks; `clear_results()` truncates it); `encoding.py` uses the last entry per key (e.g. to flag prior failures).
- **`stop.txt`** (data folder): `mode \t key`, mode `skip` or `all`, written by `request_stop()` (`POST /encode/stop`, only for the key in `current.txt` and only if `.lock/stoppable` exists, which `encode.sh` creates next to its pid so older workers that ignore `stop.txt` aren't offered a stop; it also sets the file back to offered). `encode.sh` checks it every 5 s while HandBrakeCLI runs (`stop_request`; a request for another key is stale and deleted), kills HandBrakeCLI, deletes the partial file and logs `STOPPED`. For `all` it calls `encoding.py stop-rest <i>` (`requeue_rest()`, no DB): the run's entries after number i (minus cancelled ones) go into `queue/batch-0-resumed-….txt` (sorts before other batches), the run's batches move to `done/`, and **`paused`** is created. While `paused` exists and batches are waiting, `encode.sh` waits up to 10 minutes (running replace jobs, without `caffeinate`) and exits; `POST /encode/resume` deletes it.
- **`cancelled.txt`** (data folder): `batch file name \t key` per line, entries of the current run removed in the web UI (`remove_queued()`; waiting entries in `queue/` are instead rewritten after moving the batch into `.queue-edit/`). `encode.sh` skips matching entries (still counting them in `i`/`total`) and deletes the file when the run ends; `queue_items()` shows them as `removed`, `queued_entries()` leaves them out.
- **`logs/encodes.tsv`**: `date \t key \t preset id \t quality` per finished encode (quality `rf<RF>` or `avg<kbit/s>`, computed in `encode.sh` like `presets.quality_tag()`). `encoding.encode_quality(key)` reads the last entry for a key, else looks up the preset (latest batch line, share preset, default); `suggest_name(…, quality)` puts it after the release group. `clear_results()` truncates it.
- **`logs/run.txt`**: batch file names of the worker's current run in order, written by `encode.sh` when the run starts and deleted when it ends. `current.txt`'s number counts across all of them, and `encode.sh` moves each finished batch to `done/` right away, so `encoding.run_entries()` reads the run's batches from `processing/` or `done/`; `queue_items()` and `requeue_rest()` must use it (never count only `processing/`). A finished entry's state is its result from this run (`results.tsv` time ≥ `run.txt` mtime), otherwise `skipped`.
- **`logs/current.txt`**: `key \t i \t total \t epoch` for the file being encoded. **`logs/progress.log`** is HandBrakeCLI stdout. Both are parsed by regex (`Encoding: ..., N %`, `avg N fps`, `ETA XhYmZs`) in `encoding.current_progress()` and in `status.sh`.

Scan classification order in `_scan()` (first match wins):
1. already optimized: name matches `x265|h265|hevc|FuN`, or ffprobe reports a codec in `OPTIMIZED_CODECS` (hevc, av1, vvc); stored as status `h265`
2. bad release type: `BAD_RELEASE_RE`, matched only as a separator-delimited token in the stem
3. stem already present in `_ENCODED`
4. already queued
5. skipped
6. legacy baseline
7. offered

The offered list's numbering is stored as `last_offer` and stays stable until the next scan; `queue` and `skip` refer to those numbers. Skips are keyed by full path, so a renamed file reappears.

## Configuration

Machine-specific settings live in **`config.env`** next to the scripts. It is gitignored and created from the committed template `config.example.env`, which documents every key.
- **Format:** shell `KEY="value"` lines. `encode.sh` `source`s the file; `encoding.py` parses it with `load_config()` (`shlex`, then `$VAR` expansion) and `apply_config()` turns it into `ROOT_CANDIDATES`, `ENCODED_CANDIDATES` and `NOTE_DIR_CANDIDATES`.
- **Path lists:** folder keys may list several paths separated by `:`. Both scripts use the first path that exists (`first_existing`, implemented on each side). This lets one `config.env` work natively and in the Docker container (`/media/...`).
- **Missing config:** both scripts stop with an error if `config.env` is missing or incomplete. `version` works without it.
- **New settings:** add the key to `config.example.env`, to the README's Configuration table and to `SETTINGS` in `webui.py` if it should be editable there, and read it in both scripts if both need it.
- **Path lists in the template:** folder defaults list the macOS path first and then the container path (`/media/<folder>`, `/encoded`, `/notes`), so one file works natively and in Docker.

| Setting | Where |
|---|---|
| Shares / output / Obsidian folders | `config.env` `SHARE_N` (+ `SHARE_N_NAME`, `SHARE_N_PRESET`), `ENCODED_DIR`, `NOTE_DIR` |
| Encoding settings (codec, RF, audio, crop, container) | presets in `presets/` (web UI Presets page); `preset.json` is only the bundled first preset |
| Preset selection | queue override → `SHARE_N_PRESET` → `config.env` `DEFAULT_PRESET` |
| Name suggested by Replace… | `config.env` `RENAME_CODEC_TAGS` (codec=tag pairs), `RENAME_GROUP`; patterns `OLD_CODEC_RE`, `GROUP_RE`, `END_GROUP_RE` in `encoding.py` |
| Automatic rescan, parallel ffprobe calls | `config.env` `SCAN_INTERVAL` (minutes, 0 = off), `FFPROBE_WORKERS` (empty = CPUs) |
| Per-minute Obsidian status note during encoding | `config.env` `STATUS_NOTE_ENABLED` |
| Encode inside the Docker container | `config.env` `WORKER_ENABLED`, overridden by env `WORKER_ENABLED` |
| Data folder, DB file, web address | env `ENCODING_DATA_DIR`, `ENCODING_DB_FILE`, `WEB_HOST`, `WEB_PORT`; Docker: `.env` `WEB_BIND` (host address of the port mapping, default `127.0.0.1`) and `WEB_PORT` |
| Host folders mounted into Docker | `.env` (template `.env.example`): `HOST_MEDIA_DIR` (→ `/media`), `HOST_ENCODED_DIR`, `HOST_NOTE_DIR`, `HOST_APP_DIR` |
| "Already H.265" detection (filename only, stream not probed) | `encoding.py` `HEVC_RE` |
| Excluded release types | `encoding.py` `BAD_RELEASE_RE` |
| Scanned file extensions | `encoding.py` `VIDEO_EXTS` |
| Retry timing | plist `ThrottleInterval` (30 s); `encode.sh` sleeps 300 s if NAS, HandBrakeCLI or `config.env` is missing |

Only user choices change at runtime: skipped files and the legacy baseline, stored in `encoding.db`.

Both plists (`local.plex-encoding.plist` worker, `local.plex-encoding-web.plist` web UI) are templates: their `/Users/YOUR_USER/scripts/encoding` paths are replaced with the install folder by the `sed` command in the README when they are copied to `~/Library/LaunchAgents`.

The bundled preset is named `1080p x265 (Ger/Eng) RF20`, although its actual `VideoQualitySlider` is 22.

Local files (`config.env`, `.env`, `.venv/`) and runtime artifacts (`encoding.db*`, `.secret_key`, `.scan.lock`, `state.json*`, `queue/`, `processing/`, `done/`, `logs/`, `.lock`, `replace/`, `presets/`, `cancelled.txt`, `stop.txt`, `paused`, `.queue-edit/`, `.handbrake-cache.json`) are created in the data folder and are gitignored (and excluded from the Docker image via `.dockerignore`).
