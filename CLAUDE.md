## Keep the repo generic

The repo is published on GitHub (`git@github.com:madotha/handlebreaks.git`, MIT license) and meant to be installed on any machine. Commits use the pseudonym set in the repo's local git config; never commit real names, personal email addresses or other personal data. It must stay free of anything specific to one host or person. The same applies to the GitHub wiki (`git@github.com:madotha/handlebreaks.wiki.git`, public): clone it next to this repo (`../handlebreaks.wiki`, never inside it) and set the same pseudonym in its local git config (`user.name`, `user.email`) before committing, since the global git config may hold a real name.

- Don't commit host-specific facts, setup notes or TODOs about a particular machine. This covers usernames, home paths, mounted shares, installed versions and the state of a local install. Mention them in chat or put them in the local `TODO.md`.
- Secrets (tokens, passwords, keys, `.env`) and local config or overrides go in files that `.gitignore` covers. When adding a new file or directory of that kind, or one not needed to install the tool elsewhere (runtime output, caches, editor files), add it to `.gitignore` in the same change.
- When code needs a machine-specific value, prefer a gitignored local file plus a committed example over hard-coding it.

## Versioning and changelog

- Semantic Versioning `vX.Y.Z`. The single source of truth is `__version__` in `encoding.py`, shown by `python3 encoding.py version`. It covers the whole tool, including `encode.sh`, `status.sh`, the plist and `preset.json`.
  - MAJOR: incompatible changes, such as the `state.json` schema, the queue, results or `current.txt` file formats, renamed or removed subcommands, or anything that requires reinstalling the launchd agent.
  - MINOR: new backward-compatible features, subcommands or options.
  - PATCH: bug fixes and small adjustments, including changes to filters or presets that don't change the behaviour of the interface.
- Every user-visible change gets an entry under `## [Unreleased]` in `CHANGELOG.md` ([Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format: Added, Changed, Deprecated, Removed, Fixed, Security). Pure doc or repo housekeeping doesn't need one.
- Before a release, the user tests it: develop on a branch (not `main`), build a local image from it (`docker compose -f docker-compose.yml -f docker-compose.build.yml … up -d --build`, plus the overrides the install uses) and run it in place of the published one, so the user tries the changes with real data and in their browsers. Release only after their OK; fixes go into the same branch and get tested again. Changes to stored data (database, file formats, queue: anything MAJOR) are tested in a separate instance with a copy of the data (own `CONTAINER_NAME`, `-p <name>`, data folder), so a rejected version leaves nothing behind. After the release the install switches back to the published image (`pull` + `up -d`).
- To release:
  1. Bump `__version__`.
  2. Rename `[Unreleased]` to `[X.Y.Z] - YYYY-MM-DD` and add a fresh empty `[Unreleased]` section.
  3. Check the README and the wiki against the release: setup steps, requirements and settings must work for the new version, and every release with manual steps (MAJOR releases, changed plists, `.env` keys or mounts) needs an `Updating from version X` section on the wiki's **Updating** page describing them (and a pointer in the changelog entry). Push the wiki together with the release.
  4. Commit as `Release vX.Y.Z`.
  5. Tag that commit with an annotated tag `vX.Y.Z` (`git tag -a vX.Y.Z -m "vX.Y.Z"`).
  6. After pushing the commit and tag, publish a GitHub release for the tag: title `vX.Y.Z`, notes = that version's changelog section (empty subsections dropped, internal links kept) plus `**Full changelog:** https://github.com/madotha/handlebreaks/compare/vPREV...vX.Y.Z` (`gh release create vX.Y.Z --title vX.Y.Z --notes-file <file> --verify-tag`). A tag without a release shows on GitHub with no description.
  7. Pushing the tag starts `.github/workflows/docker.yml`, which builds, smoke-tests and publishes the image `ghcr.io/madotha/handlebreaks` (tags `X.Y.Z`, `X.Y`, `X`, `latest`; amd64 and arm64, each on its own native runner). Wait for it (`gh run watch`; if no run shows up within a minute, start it with `gh workflow run docker.yml --ref vX.Y.Z`, which publishes the same way) and check it passed before publishing the GitHub release; a failed run means the release has no image. Then update the own container with `docker compose … pull` + `up -d`, so it runs exactly what users get.

  Every release commit must carry its tag. Never bump the version without tagging, and never tag a commit that isn't a release.

## HandBrake compatibility

The preset editor must cover every setting of the newest HandBrake. Whenever a new HandBrake release comes out (CLI, macOS or Windows app), and before each release of this tool:
1. Check the latest HandBrake version and its release notes (handbrake.fr/news.php, GitHub releases): new settings, encoders, filters, renamed or removed values, a new preset format (`VersionMajor`).
2. Run `python3 encoding.py preset-check` (and `--worker` with a published worker file) with the newest HandBrakeCLI. "Settings without an editor field" must be "none": add each new setting to `editor_schema()` or `audio_track_schema()` with a label, kind, choices and, if it only exists in newer versions, a hint saying so. Old settings HandBrake still exports go into `LEGACY`. Every new field also needs a description in `preset_tips.py` (`FIELD_TIPS`, and `OPTION_TIPS` for new choices that aren't self-explanatory); `preset-check` must list none without one.
3. Encoders tied to a platform or hardware need an entry in `PLATFORM_NOTES` (e.g. new hardware encoder prefixes from the Windows or macOS app), and new Apple-only audio encoders an entry in `AUDIO_ALIASES` if HandBrakeCLI elsewhere falls back to another encoder.
4. Import a preset exported from the newest macOS and Windows apps, check that an unchanged save changes nothing and that `preset-check` reports it fully supported (or explains why not).
5. Note the result in the changelog. Update the Docker image's HandBrakeCLI to the newest release: `HANDBRAKE_VERSION` and `HANDBRAKE_SHA256` in the `Dockerfile` (verify the source tarball's `.sig` with HandBrake's key from handbrake.fr/openpgp.php, fingerprint `1629 C061 B3DD E7EB 4AE3 4B81 021D B8B4 4E4A 8645`, before taking its SHA-256). The image workflow fails if `preset-check` reports settings without an editor field.

## Overview

**Handlebreaks** (the name in the web UI, docs, Docker image and container; written with a capital H): semi-automatic H.264 → H.265 (x265) re-encoding of a Plex library with HandBrakeCLI. It runs natively on macOS (launchd) or in Docker. Python 3.9+ plus zsh scripts. `encoding.py` and `encode.sh` use only the standard library and system tools. Only the web UI needs packages (`requirements.txt`: Flask, waitress, segno for the two-factor QR code). ffprobe (ffmpeg) is optional but needed for codec data. There is no build system, linter or test suite; test changes manually in an isolated data folder (`ENCODING_DATA_DIR=<scratch dir>`), and for Docker, with a separate compose project and container name (`CONTAINER_NAME=<name> docker compose -p <name>`).

**Everything is in English**: code, comments, CLI and log output, the web UI, the Obsidian notes, configs, README, wiki and other docs. Don't add German anywhere. The only exceptions are `LEGACY_PREFIXES` and `LEGACY_NOTE_HEADING` in `encoding.py`, which must match data written by version 1.x. ## Commands

```bash
python3 encoding.py scan [--json] [--no-probe]   # scan NAS (+ ffprobe), refresh list, DB and Obsidian note
python3 encoding.py queue all -3 -7 --skip-rest  # queue by number from last scan (also: 1,2,5-8)
python3 encoding.py skip 4 | skipped | unskip 2
python3 encoding.py status
python3 encoding.py version                      # print __version__ (also --version, -V); works without config
python3 encoding.py import-legacy <cache.json> <note.md>   # one-time migration from old encoding_todo.py
python3 encoding.py purge-originals [days]       # delete kept originals older than N days (default KEEP_ORIGINALS_DAYS)
python3 encoding.py stop-rest <n> [--no-pause] [--shutdown]   # encode.sh: requeue the run after entry n (pauses unless --no-pause)
zsh encode.sh                                    # run the worker manually (normally launchd or the Docker loop)
zsh status.sh                                    # live terminal progress view
python3 webui.py [--host H] [--port P]           # web UI, default 127.0.0.1:7979 (needs requirements.txt)
python3 webui.py --set-password [--user NAME]    # set the web UI account's password (creates it; re-enables password login)
python3 webui.py --disable-mfa                   # turn off two-factor authentication (lost phone)
python3 webui.py --check-settings                # config.example.env keys vs. settings fields (run by the image workflow)
python3 webui.py --check-settings                # config.example.env keys without a settings field, settings missing from it (image workflow)
docker compose up -d                             # Docker: everything in one container (pulls ghcr.io/madotha/handlebreaks:4)
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build   # Docker with an image built from this folder (local changes)
docker compose -f docker-compose.yml -f docker-compose.hybrid.yml up -d   # Docker UI/scan + native Mac encoding
```

Running `scan` or `queue` has real side effects (writes `encoding.db`, the Obsidian note, and `queue/` batches that a worker immediately picks up and starts encoding). Don't run them casually against a real install.

## Architecture

Processes coordinate only through files in the data folder (`DATA_DIR`: the program folder, or `$ENCODING_DATA_DIR`, `/data` in Docker):

- **`encoding.py`** (controller and core library): walks the shares (`shares()` from `SHARE_N` settings), gets size and mtime per file and probes new or changed files and files whose last probe failed with ffprobe (`inventory()`, `FFPROBE_WORKERS` in parallel with the lighter `PROBE_ARGS`, cached by size and mtime in the DB; every `CHECKPOINT_EVERY` files `save_checkpoint()` upserts the probe data, with status NULL for new rows, so an interrupted scan resumes). It classifies each video, stores everything in SQLite and writes `Encoding To-Do.md`. On `queue` it writes `queue/batch-<timestamp>.txt` via a temp file in `DATA_DIR` plus `os.replace`, so a worker never sees a partial file. `scan()` takes a `flock` on `.scan.lock`, so web and CLI scans can't overlap. Replacing originals is a job handoff because the web UI may not write to the library: `POST /replace` validates and calls `encoding.request_replace()` (writes `replace/<id>.json`); `encode.sh` runs `encoding.py replace-jobs` (`run_replace_jobs()`: file moves only, no database, under the flock `.replace.lock`) at start and every minute while encoding. Before touching a file it claims each job by renaming it into `replace-running/` (outside `replace/`; leftovers of a worker that died are carried out on its next run, and `encode.sh` also starts for them). Cancelling (`cancel_replace()`/`cancel_replaces()`, `POST /replace/cancel` with `id` values or `all=1`, `json=1` for the progress bar) renames the unclaimed job out of `replace/` and writes a `cancelled` result (already `synced`); whichever rename comes first wins, so a job is never both cancelled and run. `open_replaces()` gives `{key: (job id, started)}` (`pending_replaces()` is its key set); Awaiting review rows get `replace_id` (an × cancel form) while the job isn't started. The worker writes `replace-done/<id>.json` (outside `replace/`, which must be empty when idle because launchd's `QueueDirectories` starts the worker while it isn't; `load_config()` moves a version 3.8 `replace/done/` there via `migrate_replace_done()`); the dialog (`_replace_dialog.html`) and its script (`static/replace.js`, `window.ReplaceDialog.attach(root, {say, done})`) are shared by the Files page (reloads the folder level when done) and the Status page (`replace_info()` marks finished rows with their encode or as replaced via `encoding.replaced_keys()`; reloads when done). The page polls `/replace/<id>` for the job's result (only to reload when done and to show errors). Progress is shown by the bar `_replace_progress.html` (included at the top of the Status and Files pages, `static/replaceprogress.js`, `window.ReplaceProgress.kick()` after a dialog started jobs): it polls `GET /replace/progress` (`replace_progress()`) every 3 s while replaces are ongoing, every 15 s otherwise, only while the page is visible; waiting items get a Cancel button in the details list, and the bar a "Cancel waiting" button. The "wave" it shows needs no memory: the ongoing jobs (stage `waiting` in `replace/`, `moving` in `replace-running/`, or `checking` = done but not `synced` or Plex pending/scanning, `_rp_stage()`; settled ones are `done`, `failed` or `cancelled`) plus every finished job whose result file changed after the earliest request in the wave (`_rp_requested()` reads the time from the job id), repeated until stable; `_RP` only keeps the ids for the summary shown `RP_SUMMARY` s after all settled, and caches the idle answer until `replace/` or `replace-done/` change; job files are cached by mtime (`_RP_JOBS`). When the counts change while the bar has entries, `replaceprogress.js` fires a `replaceprogress` event on `document`; `status.js` then calls `poll(true)` (lists and counts, queued in `again` if a poll is running) instead of reloading the page. Result files must always be written with `write_text_atomic()` (tmp + rename): `replaced_log()` and `replace_records()` are cached by the folder's mtime, which an in-place write doesn't change. Bulk replace (`_bulk_replace_dialog.html`, `static/bulkreplace.js`, `window.BulkReplace.open(formData, {say, done})`): `POST /replace/preview` lists files with a finished encode (ticked `key`/`folder` values expanded with the filters, or `all=1` = every non-`h265` file whose stem has an encode; the `waiting` status is only set by scans, so files encoded since the last scan are still `queued`, and `level_context()` shows them as `waiting` too; it also marks the file in `current.txt` as `encoding` and an offered file whose last result is FAIL as `failed`, and `activity_version()` puts both into the folder cache version) with suggested names (codecs probed in parallel), `POST /replace/bulk` validates all rows (unknown, pending, missing encode, bad or duplicate name) before creating any job. `run_replace_jobs()` moves the files of each job and writes its result at once (Plex is the web UI's job, see below). Name fields are single-line textareas made by `window.nameField(field, onEnter)` (`replace.js`): they grow with the text, Enter submits, line breaks are stripped. The dialog pre-fills the encode's name, then asks `/replace/suggest?key=…` for `encoding.suggest_name()` (codec of the encode via ffprobe; keeps the field if it was edited meanwhile). Bringing the result into the DB is the web UI's job, not the page's: `sync_replaces()` (under `REPLACE_SYNC`) rescans the folder of every finished job without `synced` (`unsynced_replaces()`), then sets `synced` in its `replace-done/` file (`mark_replace_synced()`); it runs every 10 s in `replace_sync_loop()` and from `/replace/<id>`, and returns False (retry later) while another scan holds the scan lock. Pending jobs (`pending_replaces()`) show as "Replacing…" instead of the button; `clear_results()` keeps unsynced job results. `replace_one()` never overwrites another file, keeps or deletes the original, and rolls back on failure. Deleting finished encodes is done by the web UI itself (like deleting kept originals): `POST /encodes/delete` (`key` values; `requeue=1` with `preset`, "" = the share's) from Status → Awaiting review (bin per row in `_replace_button.html`, "Delete selected…"; dialog `_delete_encode_dialog.html`, `static/deleteencode.js`) leaves out keys with an open replace or in the queue; the Files page has the same bin and the × for waiting replaces in its actions column (`json=1` answers of `/encodes/delete` and `/replace/cancel`, `window.onEncodeDeleted` in `files.js` reloads the folder level; `level_context()` adds `enc_bitrate`, `preset_name` and `replace_id`); `enc.delete_encoded(names)` removes only regular video files directly in the output folder (plus `@eaDir/<name>`), then `write_batch()` queues them again, or `enc.unwait()` sets their `waiting` rows back to `offer`/`skipped` until the next scan. The tab's Preset column comes from `enc.encode_presets()` (`encodes.tsv`). Awaiting review, History, Queue and Kept originals have a Bitrate column (`bitrate_cell()` in `_cells.html`), the first three also Codec and Resolution: the original's `files.bitrate` (History: `history_bitrates()` via `add_info()`, the replacing file's via `new_key` for REPLACED rows, which `replaced_log()` carries) and, while the encode is in the output folder, `encode_bitrate()` = its size over the original's duration (History: only for the page's rows, `history_encodes()`). A kept original goes to `<output folder>/.replaced/<path in the share>` (no share number in the path). Unlike replacing, deleting kept originals is done by the web UI itself (the output folder is writable even in Docker): `kept_originals()` walks the folder (only `VIDEO_EXTS` files; skipping symlinks and Synology's `@eaDir`) and joins each file to its replace job via `replace_records()` (`new_key`, finish time; otherwise the file's ctime counts as "kept since"), `replacement_state(new_key)` checks the replacing file (ok with its size, missing, offline via `reachable()`, unknown), `split_kept()` holds back originals whose state is in `KEPT_BLOCKED` (missing/offline) unless `force` (`POST /originals/delete` with `force=1`, the checkbox "Also when the replacement is missing" shown when a row on the page is blocked), `purge_kept()` always holds them back and returns `(count, freed, held)`; `delete_kept(keys)` removes only regular files that resolve inside `.replaced/` and removes the `@eaDir/<name>` index data of the deleted file and prunes empty folders, `purge_kept(days)` deletes the old ones (`KEEP_ORIGINALS_DAYS`, `python3 encoding.py purge-originals [days]`, hourly in `originals_purge_loop()` of the web UI). Plex (only with `PLEX_URL`/`PLEX_TOKEN`): the worker makes no Plex calls; `replace_one()` puts the new file in before the original leaves (new name), or swaps it in from a hidden `.<name>.handlebreaks-tmp` with `os.replace` (same name; the kept original via `os.link`, else moved), so Plex never sees the item without a file. `run_replace_jobs()` stores `plex.job_info()` as `plex` in the result (`state` pending, Plex-side `path`/`old_path` via `PLEX_PATH_MAP` (`path_map()`, `to_plex()`), `size`, `same_name`, `queued`). The web UI's `plex_sync()` (in `replace_sync_loop()`, after `sync_replaces()`) passes the open ones (`enc.plex_open_jobs()`) to `plex.advance()`: per folder, once no replace came for `SETTLE` s (at most `MAX_WAIT`), one `/library/sections/<id>/refresh?path=<folder>` plus `PUT /library/metadata/<ratingKey>/analyze` for same-name files (`_scan()`, state scanning); after `CHECK_AFTER` s `_check()` asks for the item's parts (`item_files()`; the item is found by walking `/library/sections/<id>/folder`, which merges all folders of a library): ok if the new path with the stored size is listed and (new name) the old path isn't; otherwise one more scan after `RETRY_AFTER` s, then failed (`reason`); skipped if no library contains the folder; failed if Plex stays unreachable for `UNREACHABLE` s. Changes go through `enc.update_replace_result()` (re-reads the file under a lock, so `synced` and `plex` don't overwrite each other). failed/skipped add a `plex_failed` event; the state shows as a badge on History's REPLACED rows (`replaced_log()` carries it), `replace_status()` appends `plex.note()` to the message, and `purge_kept()` skips originals whose state is in `PLEX_UNCONFIRMED` or whose replacement is missing or offline (`kept_info()` warns `plex`). The token goes only into the `X-Plex-Token` header; never print or log it. `PLEX_URL` may list several addresses, the first answering one is used. `scan(path=key)` checks one file or folder (the web UI's ↻ buttons, always with `force`): it walks only that path (guarded against leaving the share), replaces only its rows, and doesn't touch `last_scan` or the per-share scan times. `scan(only=[prefixes], force=…)` scans single shares: `save_files()` then replaces only those shares' rows, the offered list and summary are rebuilt from the whole `files` table, and `force` skips the ffprobe cache. The last scan time per share is stored in `meta` as `share_scan:<prefix>`. `load_config()` also migrates a version 2.x `config.env` (`migrate_v2()`, under `.migrate.lock`) and makes sure a preset and `DEFAULT_PRESET` exist. `write_config()` is the only writer of `config.env` (web UI and migration).
- **`presets.py`**: the preset store, `presets/<id>.json` in the data folder, each a HandBrake export file with one preset. The id is a slug fixed at creation; shares and batch lines refer to it, so renaming is safe. It also reads what the installed HandBrakeCLI supports (`capabilities()`: encoders, encoder speed presets, containers, mixdowns, preset format version; `builtin_presets()`; `from_builtin()` via `--preset-export`), cached on disk in `.handbrake-cache.json` (`_disk_cache()`, keyed by the HandBrakeCLI path, size and mtime), and `verify()` makes HandBrakeCLI load a preset before it's saved. Nothing about HandBrake's options is hard-coded except `FALLBACK` for machines without HandBrakeCLI. The editor is schema-driven: `editor_schema(caps)` lists every setting per tab (`F(key, label, kind, options, hint, show, **attrs)`; kinds text, int, float, bool, select, langs, multi, json; options may depend on another field, `show` hides a field unless another has given values, `!x` = not), `audio_track_schema()` the fields of one `AudioList` entry. Fields are grouped into sections with `G("Section", F(…), …)` (the field dicts get `group`; `editor()` returns `[(tab, [(section, [field])])]`). Descriptions live in **`preset_tips.py`**: `FIELD_TIPS[key]` (what the setting does) and `OPTION_TIPS[key][value]` (what a choice means); `_resolve()` adds them as `tip` and `option_tips`, the template shows an ⓘ button (`data-info`, tooltip via `data-tip`, click expands `[data-tip-text]`) and `preset_edit.js` writes the chosen option's text into `[data-option-tip]` and puts a dot on tabs whose fields differ from the loaded state. `editor()` resolves values and choices for the template (`preset_edit.html`, `static/preset_edit.js`: tabs, dependent selects, show rules, tracks named `a<n>-<key>` with `a<n>-_orig`), and `apply_form()` parses the form back (`_store()` keeps unchanged values exactly and doesn't add unset defaults, so an unchanged save is a no-op; settings outside the schema except `INTERNAL` are edited generically under "More"). `capabilities()` also reads per-encoder tunes, profiles and levels, filter presets and tunes, sample rates, dither methods, the HandBrake version, the platform and every setting the CLI knows (`preset_keys`/`track_keys`, from its own preset export); `encode.sh` publishes the worker's capabilities to `handbrake-worker.json` (`encoding.py handbrake-caps`, in the background, only when HandBrakeCLI changed), and `webui.encodes_here()` decides whether the editor uses this machine's or the worker's (`presets.editor_capabilities()`: Docker with `WORKER_ENABLED=0` uses the worker file; then `verify()` only checks against its lists). `editor()` marks fields the encoding CLI doesn't know (`unsupported`), `compatibility()` describes the encoding CLI and notes for the preset (newer preset format, ignored settings, unavailable values, `PLATFORM_NOTES`), `audit()` backs `encoding.py preset-check` (it also lists fields without a `FIELD_TIPS` entry); bump `CAPS_VERSION` when it returns new keys (it's part of the disk cache key).
- **`encode.sh`** (worker): started by launchd (`local.plex-encoding.plist`: `QueueDirectories` on `queue/`, `processing/` and `replace/`, which must therefore be empty when there's nothing to do, plus `RunAtLoad`; it exits at once without touching the library if there are no batches or replace jobs) or by the loop in `docker-entrypoint.sh`. It moves batches `queue/ → processing/ → done/`, encodes into `<ENCODED>/.inprogress/` and moves the file to `<ENCODED>/` only on success. A `mkdir`-based `.lock` (stale-PID cleanup) keeps it single-instance. It uses `caffeinate` where available, and exits or sleeps if the NAS, HandBrakeCLI or `config.env` is missing, so it gets retried. A share counts as reachable only if its folder isn't empty (`reachable()` in `encode.sh`, `encoding.reachable()`: an unmounted share leaves an empty mount point). If the source is missing or HandBrakeCLI fails while the entry's share or the output folder is offline (`offline()`), the run is interrupted instead (`went_offline()`): `encoding.py stop-rest <i-1> --no-pause` requeues the current entry and the rest, no result is written. Stopped from outside (SIGTERM/SIGINT: `docker stop`, launchd, Ctrl+C), the `shutdown` trap ends the run cleanly: it passes the signal to a running `encoding.py replace-jobs` (which finishes the current job and starts no new one, `REPLACE_STOP`), kills HandBrakeCLI and deletes the partial file, and during a run calls `stop-rest <done_upto> --no-pause --shutdown` (`done_upto`: entries before the current one, or the current one once `result()` logged it), which names the batch `batch-0-resumed-shutdown-…`; from HandBrakeCLI's end until the entry's result is logged (`critical=1`, the move out of `.inprogress/`) the signal is deferred (`on_signal`, `end_critical`), so a finished encode is never thrown away or left without its result so `run_events()` words the "Run interrupted" notification as a stopped worker. Children that may take long (`replace-jobs`, `nap` instead of `sleep` after the trap is set) run in the background plus `wait`, because zsh runs a trap only after a foreground command ends. Before 3.20 the EXIT/INT/TERM trap only removed the lock, so a stopped worker kept encoding until killed. Scans refuse offline shares (`walk_library()`), `webui.offline_now()` (`enc.offline_shares()`, checked at most every 30 s) feeds the "Not reachable" banner in `base.html` and holds back automatic scans.

At most 4 popups show (3 on phones); `layout()` hides the older ones (`hidden`, so their bar animation doesn't run until they show) behind the `.toast-more` chip ("+N more", then "Close all" once expanded, `.toasts.expanded` scrolls). A popup's time bar (`.toast-bar`, CSS animation of `NOTIFY_SECONDS`) is its timer: it hides on `animationend`, and the animation pauses while `.toasts` is hovered or the popup has focus. Popups on screen are kept per tab in `sessionStorage` (`events:open`: event, `total` seconds, ms `left` from the animation's computed progress), saved on show, close, `pagehide` and when the tab is hidden, and shown again by `restore()` on the next page (bar continued with a negative `animation-delay`, class `restored` without slide-in; on a back/forward-cache `pageshow` they are rebuilt from storage). Events of the user's own actions (queue, remove, delete) are deliberately not added. `enc.prune_events()` (hourly) keeps 7 days and at most 500 rows. All POSTs need a session CSRF token (an empty session token never matches). The session key is in `DATA_DIR/.secret_key`. Login (**`auth.py`**): one account in `auth.json` in the data folder (`user`, werkzeug `hash` with scrypt, PBKDF2 on Pythons without it, `generation`, `changed`; written 0600 via tmp + rename, never in `config.env`). `before()` sends every endpoint outside `PUBLIC_ENDPOINTS` (static, health, manifest, service worker, offline, login, setup, logout) to `login_required()` unless `signed_in()` (session `auth_user` and `auth_gen` match the account): navigations (`wants_page()`: `Sec-Fetch-Mode: navigate`, else GET with `text/html`) are redirected to `/login` (or `/setup` while there is no account) with `next`, background requests get 401 JSON plus `X-Login`, which `static/session.js` (in `<head>` of `base.html`, wraps `fetch`) turns into a redirect. `/setup` creates the account only with the setup code (`auth.setup_code()`, `.setup-code` 0600, printed to stderr by `announce_setup_code()` at start and when the page is first shown; deleted with the account's creation). `start_session()` clears the session first; `remember` makes it permanent (`AUTH_SESSION_DAYS`, applied as `permanent_session_lifetime` on every request, also the signature's max age). A new password or `POST /settings/security/signout` raises `generation`, which ends every other session (the acting one is updated). Failed logins and setup codes are throttled per `remote_addr` in memory (`auth.failed()`/`wait_seconds()`). `login.html` is its own page (no `base.html`: it would poll `/events`). Settings → Login & security (`security` in `SETTINGS_PAGES`, account forms `POST /settings/security/account` and `/settings/security/signout` outside the settings form, `security_context()`). Single sign-on (**`oidc.py`**, standard library only): code flow with PKCE S256, `state` (in `_PENDING` in memory, bound to the browser by `session['oidc_state']`) and `nonce`; the ID token comes from the token endpoint over verified TLS, so its signature isn't checked (OIDC Core 3.1.3.7) but `iss`, `aud`/`azp`, `exp`, `iat`, `nonce` are; userinfo adds claims (groups). `GET /login/oidc` → provider → `GET /login/oidc/callback` (both in `PUBLIC_ENDPOINTS`); errors go to the sign-in page via `session['login_error']`. `oidc.allowed()` checks `AUTH_OIDC_ALLOWED_USERS` (sub, preferred_username or email; `*` = everyone the provider lets in) and `AUTH_OIDC_ALLOWED_GROUPS` (groups claim). A successful sign-on records `oidc_ok` (issuer, client) in `auth.json`; only then does `other_sign_in_methods()` count it, and only then can `AUTH_PASSWORD_LOGIN` be 0: `password_login()` (env var wins, 1 on / 0 off) stays on otherwise, so nobody is locked out; `needs_setup()` = password login on and no account. Sessions carry `auth_method`; OIDC sessions carry `auth_policy` (`oidc_policy()`: hash of issuer, client, allowed users and groups), so changing any of them ends them; password sessions end when the password login is off. Login settings are read by `setting(key)` (env var for `env=True` settings, else `config.env`, else the default). `POST /settings/oidc/test` (`oidc.test()`: discovery, then the token endpoint with a dummy code must answer `invalid_grant`, not `invalid_client`) uses the form's values; an empty secret field uses the stored secret only for the same issuer and client (`oidc_secret_for()`, `oidc_secret_rule()` like the Plex token), `oidc_settings_rule()` checks the fields together. Connection-test buttons are `[data-conn-test=<url>]` with a `[data-conn-result]` sibling (`static/settings.js`). Env-set settings are shown with the env's value, disabled and without default/reset (`data-locked`); `shown_env()` masks keys containing TOKEN, SECRET or PASSWORD wherever env values are shown. `--set-password` also writes `AUTH_PASSWORD_LOGIN=1` to `config.env`. Two-factor for the password account (TOTP, RFC 6238: SHA-1, 6 digits, 30 s, ±1 step; `auth.totp()`/`code_step()`/`check_mfa()`): `mfa` in `auth.json` holds the secret, `last_step` (a code works once) and SHA-256 hashes of 10 recovery codes. After a correct password, `login()` puts `mfa_pending` (user, generation, time, remember, next; 5 min) into a cleared session and sends the browser to `GET/POST /login/code` (`login_mfa`, public, throttled like the password). Settings: `POST /settings/security/mfa/start` keeps a new secret in `session['mfa_new']` until `…/mfa/confirm` (password + a code for that secret) stores it, raises the generation and shows the recovery codes once (`session['mfa_recovery_show']`); `…/mfa/recovery` and `…/mfa/disable` need password and a current code (`password_and_code()`). The QR code is inline SVG from `segno` (`qr_svg()`, black on white; without segno only the key is shown). `--disable-mfa` turns it off from the command line. The session cookie gets `Secure` when the request came over HTTPS (`SessionInterface`). Never log passwords, hashes or the session secret. The web UI still binds to 127.0.0.1 by default.
- **Docker**: the published image is `ghcr.io/madotha/handlebreaks` (built for every `v*` tag by `.github/workflows/docker.yml`; `docker-compose.yml` uses tag `${HANDLEBREAKS_TAG:-4}`, so a MAJOR release never arrives with a plain `pull`), a local build is `handlebreaks:local` (`docker-compose.build.yml`; test local changes with it, the plain compose file runs the published image). The `Dockerfile` has two stages: `handbrake` builds HandBrakeCLI from HandBrake's official source tarball (`HANDBRAKE_VERSION`, pinned `HANDBRAKE_SHA256`; CLI only, its bundled contribs are checksummed by HandBrake's build) and writes the Debian packages of the libraries it links (`ldd` → `dpkg -S`) to `runtime-packages`, which the final stage installs next to Debian's `ffmpeg` (ffprobe); HandBrake's `COPYING` and a `SOURCE` note go to `/usr/share/doc/handbrake-cli/`. That stage is cached (GitHub Actions cache per architecture) until its version changes; a cold build takes roughly 15–40 minutes. HandBrake is configured with `--disable-numa`: x265 built with libnuma gets no thread pool on kernels without NUMA (Docker Desktop's LinuxKit VM) and encodes about 4x slower. The workflow's smoke test checks that the tag matches `__version__`, that HandBrakeCLI and ffprobe run, that HandBrakeCLI doesn't link libnuma and x265 encodes a test clip with a thread pool, that `preset-check` lists no settings without an editor field and that the web UI answers `/health` with the compose file's hardening. Container and compose project are named `handlebreaks` (`container_name: ${CONTAINER_NAME:-handlebreaks}`; a second instance next to it, e.g. a test with `docker compose -p <name>`, needs its own `CONTAINER_NAME`), the service stays `encoding` (`docker compose exec encoding …`). Internal identifiers keep their old names on purpose, because renaming them would break existing installs: the launchd labels `local.plex-encoding(-web)`, the compose service and the native default folder `~/scripts/encoding`. The `Dockerfile` copies the Python modules by name (`auth.py encoding.py funfacts.py oidc.py plex.py presets.py preset_tips.py webui.py`): add every new module there. `docker-entrypoint.sh` creates `config.env` from the template, runs the worker loop (every 30 s, if jobs exist in `queue/`, `processing/`, `replace/` or `replace-running/` and `WORKER_ENABLED` is 1; the env var overrides `config.env`) and the web UI as background children and waits: on SIGTERM (tini, `init: true`) it stops the worker first (the loop passes the signal to `encode.sh`), then the web UI, and exits 0; if the web UI ends by itself it exits 1 so `restart` brings the container back. `docker-compose.yml` gives it `stop_grace_period: 2m` and hardens it (`read_only` with a `/tmp` tmpfs, `cap_drop: ALL`, `no-new-privileges`), so anything that writes must go to a volume or `/tmp`. The image is Debian 13 with the HandBrakeCLI built in the first stage, which maps the preset's `ca_aac` to `av_aac` on its own. `docker-compose.hybrid.yml` bind-mounts the native install folder as `/data`, forces `WORKER_ENABLED=0` (the cross-VM `.lock` PID check would not prevent two workers), and moves the DB to its own volume (`ENCODING_DB_FILE`), because SQLite must not be shared across the Docker VM boundary.

**SQLite (`encoding.db`, WAL)**, schema in `SCHEMA`:
- Tables:
  - `meta`: `last_offer` JSON, `last_scan`, `results_offset`, `events_results_rowid`, `events_run` (JSON of the run `event_loop()` watches: `run.txt` mtime and start, so a run that ends while the web UI is down still gets `run_done`)
  - `baseline`, `skipped`, `known`
  - `results`: imported from `results.tsv` on every `load_results()`
  - `events`: `id` (AUTOINCREMENT, so ids are never reused), `at` (`YYYY-MM-DD HH:MM:SS`), `kind`, `key`, `detail`, `level`: notifications of the web UI (additive table, older versions ignore it)
  - `dismissed`: `key`, `at` (`YYYY-MM-DD HH:MM:SS`): entries of the key up to `at` are hidden on the Status page (additive table, `CREATE TABLE IF NOT EXISTS`; older versions ignore it)
  - `files`: inventory with ffprobe fields, `status` ∈ `STATUS_LABELS` and `added` (epoch, first seen: kept by `inventory()` across scans; the scan time for new files, the file's mtime on a share's first scan; `migrate_added()` adds the column to older databases and fills it from `mtime`; `sync_replaces()` copies it to a replaced file's new key)
- `load_state()`/`save_state()` keep the old `state` dict interface.
- A v1 `state.json` is imported once by `migrate_state_json()` and renamed to `state.json.migrated`.
- Changing the schema or these meanings is a MAJOR change.

macOS quirk: when launchd starts `encode.sh`, `/bin/mv` and `/bin/rm` get "Operation not permitted" on the NFS library/output share, while Python's `os`/`shutil` calls work (verified with `launchctl submit`). Every file operation on the share in `encode.sh` must use the `fs` helper (Python); plain `mv`/`rm` are only fine for local files (queue, logs, lock).

Shared file contracts (change both sides together):
- **Keys**: every file is identified as `share<N>/<rel path>`, where N is the share number from `SHARE_N`. Names (`SHARE_N_NAME`) are display-only. The numbers are part of stored keys, so they must never be renumbered or reused: the web UI comments out removed shares, and `next_share_number()` skips any number that appears in `config.env`, even commented out. Batch files contain one entry per line: `key` or `key<TAB>preset id` (an override chosen when queueing). `encode.sh` looks up the prefix in `ROOTS` and picks the preset as override, then `SHARE_N_PRESET`, then `DEFAULT_PRESET`; `status.sh` and `queued_entries()` read the same format. Keys from version 1.x (`Filme/`) and 2.x (`Movies 2/`) are translated by `legacy_key()` with the `v2_prefix_map` stored in the `meta` table, whenever old `state.json` or `results.tsv` lines are imported.
- **`logs/results.tsv`**: `date \t STATUS \t key`, status ∈ OK/FAIL/MISSING/EXISTS/STOPPED. Written by `encode.sh`, imported into the DB incrementally (byte offset in `meta` `results_offset`, reset when the file shrinks; `clear_results()` truncates it); `encoding.py` uses the last entry per key (e.g. to flag prior failures).
- **`stop.txt`** (data folder): `mode \t key`, mode `skip` or `all`, written by `request_stop()` (`POST /encode/stop`, only for the key in `current.txt` and only if `.lock/stoppable` exists, which `encode.sh` creates next to its pid so older workers that ignore `stop.txt` aren't offered a stop; it also sets the file back to offered). `encode.sh` checks it every 5 s while HandBrakeCLI runs (`stop_request`; a request for another key is stale and deleted), kills HandBrakeCLI, deletes the partial file and logs `STOPPED`. For `all` it calls `encoding.py stop-rest <i>` (`requeue_rest()`, no DB): the run's entries after number i (minus cancelled ones) go into `queue/batch-0-resumed-….txt` (sorts before other batches), the run's batches move to `done/`, and **`paused`** is created. While `paused` exists and batches are waiting, `encode.sh` waits up to 10 minutes (running replace jobs, without `caffeinate`) and exits; `POST /encode/resume` deletes it.
- **`cancelled.txt`** (data folder): `batch file name \t key` per line, entries of the current run removed in the web UI (`remove_queued()`; waiting entries in `queue/` are instead rewritten after moving the batch into `.queue-edit/`). `encode.sh` skips matching entries (still counting them in `i`/`total`) and deletes the file when the run ends; `queue_items()` shows them as `removed`, `queued_entries()` leaves them out.
- **`logs/encodes.tsv`**: `date \t key \t preset id \t quality` per finished encode (quality `rf<RF>` or `avg<kbit/s>`, computed in `encode.sh` like `presets.quality_tag()`). `encoding.encode_quality(key)` reads the last entry for a key, else looks up the preset (latest batch line, share preset, default); `suggest_name(…, quality)` puts it after the release group. `clear_results()` truncates it.
- **`logs/run.txt`**: batch file names of the worker's current run in order, written by `encode.sh` when the run starts and deleted when it ends. `current.txt`'s number counts across all of them, and `encode.sh` moves each finished batch to `done/` right away, so `encoding.run_entries()` reads the run's batches from `processing/` or `done/`; `queue_items()` and `requeue_rest()` must use it (never count only `processing/`). A finished entry's state is its result from this run (`results.tsv` time ≥ `run.txt` mtime), otherwise `skipped`.
- **`logs/worker-wait.txt`**: `kind \t prefix \t path \t error` (kind `offline`, `denied` or `handbrake`), written by `encode.sh` while it waits for the library or HandBrakeCLI instead of encoding (a share folder that exists but `ls` can't list is `denied`, with the error, e.g. macOS's `Operation not permitted` for launchd jobs) and deleted once the checks pass. `encoding.worker_wait()` reads it (ignored when older than `WORKER_WAIT_FRESH`, 15 min) for the banner in `base.html` (`worker_wait` in the template context; an `offline` share already in the "Not reachable" banner isn't repeated).
- **`logs/current.txt`**: `key \t i \t total \t epoch` for the file being encoded. **`logs/progress.log`** is HandBrakeCLI stdout. Both are parsed by regex (`Encoding: ..., N %`, `avg N fps`, `ETA XhYmZs`) in `encoding.current_progress()` and in `status.sh`.

Scan classification order in `_scan()` (first match wins):
1. already optimized: name matches `x265|h265|hevc|FuN`, or ffprobe reports a codec in `OPTIMIZED_CODECS` (hevc, av1, vvc); stored as status `h265`
2. bad release type: `BAD_RELEASE_RE`, matched only as a separator-delimited token in the stem
3. stem already present in `_ENCODED`
4. already queued (`pending_keys()`: waiting or encoding; files that finished in the current run don't count)
5. skipped
6. legacy baseline
7. offered

The offered list's numbering is stored as `last_offer` and stays stable until the next scan; `queue` and `skip` refer to those numbers. Skips are keyed by full path, so a renamed file reappears.

## Configuration

Machine-specific settings live in **`config.env`** next to the scripts. It is gitignored and created from the committed template `config.example.env`, which documents every key.
- **Format:** shell `KEY="value"` lines. `encode.sh` `source`s the file; `encoding.py` parses it with `load_config()` (`shlex`, then `$VAR` expansion) and `apply_config()` turns it into `ROOT_CANDIDATES`, `ENCODED_CANDIDATES` and `NOTE_DIR_CANDIDATES`.
- **Path lists:** folder keys may list several paths separated by `:`. Both scripts use the first path that exists (`first_existing`, implemented on each side). This lets one `config.env` work natively and in the Docker container (`/media/...`).
- **Missing config:** both scripts stop with an error if `config.env` is missing or incomplete. `version` works without it.
- **New settings:** add the key to `config.example.env`, to the wiki's Configuration page and as an `S(…)` entry in `SETTINGS_PAGES` in `webui.py` (with its default; a key edited by a form part of its own goes into `SPECIAL_KEYS`), and read it in both scripts if both need it. `python3 webui.py --check-settings` must report none missing on either side. A new settings page goes into an existing sidebar group if one fits (System is meant for login, security and backup pages).
- **Path lists in the template:** folder defaults list the macOS path first and then the container path (`/media/<folder>`, `/encoded`, `/notes`), so one file works natively and in Docker.
